# 课间 · 手机课表

手机优先的本地 PWA：上传课表截图、校对课程草稿、保存周课表。React + TypeScript + Vite，无后端和账号系统。当前已完成第一阶段产品闭环，以及第二阶段第一部分的工业视觉系统升级。

**当前是演示识别，不是真实 OCR。任意图片都会返回同一份参考课程数据，只使用你选择的学期和周次。** 所有课程信息都应在导入前人工确认。截图不会上传或持久保存，也不会读取教务系统账号、密码或 Cookie。

## 在电脑上启动

建议使用 Node.js 24 LTS 和 npm，项目已提供锁定依赖的 `package-lock.json`。

```powershell
cd C:\class_desktop
npm ci
npm run dev
```

按终端提示打开地址（通常为 `http://localhost:5173`）。依赖已安装时可跳过 `npm ci`。

正式构建及预览：

```powershell
npm run build
npm run preview -- --port 4173 --strictPort
```

打开 `http://localhost:4173`。不要直接双击 `dist/index.html`，请通过 Web 服务访问。

## 在手机上使用

1. 手机与电脑连接同一 Wi-Fi。
2. 在电脑运行 `npm run dev` 或 `npm run preview`。
3. 在手机浏览器打开终端显示的 Network 地址，例如 `http://192.168.1.10:4173`。这个示例地址需要替换为电脑实际地址。
4. 若无法连接，检查 Windows 防火墙是否允许 Node 在当前私人网络中访问，以及路由器是否开启设备隔离。

局域网 HTTP 支持页面预览、导入和编辑。安装 PWA 与离线缓存需要安全来源：电脑可使用 localhost；手机通常需要 HTTPS。正式构建会缓存应用页面，首次在线打开并完成 Service Worker 安装后可离线刷新。开发模式不用于验证离线功能。

电脑浏览器、手机浏览器以及不同端口/域名各自保存数据，第一阶段没有跨设备同步。电脑测试里的课程不会自动出现在手机。

## 使用流程

1. 首次设置学期名称、第一周周一日期和总周数。默认日期 `2026-08-31` 根据参考截图推算，应按学校校历核实。
2. 在“导入”选择 PNG、JPG 或 WebP 截图，每张不超过 15 MB，每批最多 12 张。
3. 为每张图片确认学期、周次，生成演示草稿。需要时可展开“查看原图与识别提示”。
4. 编辑、添加或删除课程，核对教室、教师、节次和周次。周次支持 `1,3,5-8`，不会推断未提供截图的周。
5. 时间冲突会提示；需要明确勾选保留重叠安排才允许导入。
6. 确认导入后查看周课表，点击课程可继续修改；左右滑动或点击箭头切换教学周。
7. “导入”页可撤销最近一次实际产生变更的导入。如果相关课程之后已被编辑或删除，会拒绝直接撤销以保留修改。

同一学期、名称、教室、教师相同的课程可合并，星期和节次相同的安排合并周次。不同教室保留为独立课程记录。重复导入相同内容不会制造新课程或空批次。

## 第二阶段视觉系统

“课间”现在采用原创的“高明度工业终端”界面：灰白色承担主要阅读区域，黑色承担导航与重点状态，信号黄色只用于当前页面、主要操作和关键进度。错误、警告、成功分别使用红、橙、青绿色；课程自身使用低饱和色，不与系统主色争夺层级。

- 今日页将下一节课程放在深色主面板中，配合倒计时、状态轨道和纵向课程任务序列。
- 周课表保留七天、11 节、连续节次和重叠分栏算法，改用硬边课程块、工程网格和当前星期黄色标识。
- 导入页使用三阶段数据接入流程；上传、警告、冲突、写入完成具有一致的状态语言。
- 设置页以终端档案方式组织学期和本地数据，不增加与课程管理无关的装饰统计。
- 手机使用保留文字的深色底部导航；桌面使用固定侧栏。常用触控区域至少约 44px，并处理底部安全区。
- 支持 `prefers-reduced-motion`。系统请求减少动效时，页面进入、状态脉冲和交互过渡会缩短到近乎即时。

视觉实现没有包含、裁切或重新分发任何参考游戏图片、角色、Logo、图标或商标元素。应用标志、网格、切角和界面组件均为本项目原创代码与 SVG。

设计令牌位于 `src/styles/tokens.css`，全局框架位于 `src/components/AppShell.tsx`。样式按基础、框架、组件、页面、表单、动效和响应式拆分在 `src/styles/`，后续增加日程功能时应复用这些令牌与组件，不要在页面内另建一套颜色和按钮规则。

## 数据与限制

- 使用 localStorage，键名 `kejian.app.v1`；课程、学期、导入快照一起保存。
- 每次先完成持久化再更新界面；存储已满或禁用时显示错误。
- 清除浏览器数据会失去记录，建议在“设置”导出 JSON 备份。第一阶段提供导出，尚无备份恢复界面。
- 图片仅保留在当前导入页面的内存中，离开页面后释放；未确认草稿离开页面后不会保留。
- 周课表使用每个教学周的课程规则，不预生成整个学期的大量事件。
- 第一阶段尚未支持真实 OCR、普通日程导入、推送提醒、云同步、学校登录或校历自动调休。
- 参考截图中周一 5–6 节的“日语（一）”归属不明确，演示数据保留提示，需要手动补充核对。
- 浏览器测试为 Edge 下的手机尺寸模拟；未宣称已在真实 iPhone Safari 或 Android 设备完成测试。

浏览器测试使用已安装的 Microsoft Edge，需先构建。默认用项目内 PNG 测试文件选择，因为演示识别器不依赖图片内容。可以用真实截图验证上传路径：

```powershell
$env:TIMETABLE_SCREENSHOT = 'C:\你的目录\课表.jpg'

```

测试覆盖教学周和日期边界、离散周次、合并/冲突、撤销保护、链式重叠分栏、HTTP UUID 兼容、截图增删改、刷新保存、重复导入和离线页面。视觉回归额外检查 360、390、430、768、1440px 宽度、超长课程名、课程编辑器、导入固定操作栏、减少动效模式和页面级横向溢出。报告与截图在 `test-results`。运行器自动启动 4173 端口预览；若自行启动该端口，应确保它指向本项目最新构建。

## 第二阶段：接入真实截图识别

实现 `TimetableImageRecognizer`，保持输入为 `File + semesterId + weekNumber`，输出为课程草稿和警告。适配器放在 `src/services/`，替换导入页的识别器依赖，不修改课程存储与合并规则。

建议先针对学校固定课表布局，检测星期列与节次行、合并色块和连续节数，再进行中文 OCR。逐条保留低置信度/缺失字段警告，继续使用现有人工校对流程；周次必须由截图证据或用户确认提供。

选型时用实际截图评估中文小字、跨行课程名、教室、同格多门课程的识别率和手机耗时。浏览器本地 OCR 能保持图片不离开设备；如选择远程识别，应在上传前明确告知用户并取得同意，服务端保管密钥，不能将密钥打包进前端。第一阶段尚未选择或调用任何外部识别服务。

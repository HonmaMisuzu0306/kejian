# 课间课表扫描第一阶段开发 Prompt

请在 `C:\class_desktop` 中继续开发“课间”，实现课表截图扫描第一阶段，并发布实验版本 `v1.0.1`。

## 阶段目标

在不增加后端、不上传截图、不读取教务账号信息的前提下，将现有模拟识别器替换为真正读取图片像素的本地识别适配器。第一阶段只支持南信大移动教务系统的竖屏周课表截图，继续使用现有人工校对、冲突检查、保存和撤销流程。

## 功能要求

- 保留统一的 `TimetableImageRecognizer` 接口，识别逻辑独立于页面。
- 根据当前教务系统固定版式定位星期列和第 1–11 节网格。
- 通过背景色检测课程块，推导星期、开始节次、结束节次，并正确拆分相邻课程。
- 使用浏览器本地中文 OCR 识别课程名和教室；OCR 引擎、核心文件和简体中文语言数据必须随 PWA/APK 打包，不依赖远程 CDN。
- 显示初始化及逐课程识别进度；失败时提供能指导用户重新截图的中文错误。
- 输出始终是“实验性识别草稿”，低置信度、缺失课程名或教室必须提示用户核对。
- 不根据单张截图猜测其他周次；使用用户在上传页确认的学期和周次。
- 不宣称支持其他学校、横屏、裁切图或不同主题。无法识别的版式应停止并保留人工处理入口。
- 课程仍以离散周次数组保存，沿用已有合并、冲突检测、编辑、导入和撤销逻辑。

## 数据与隐私

- 截图只保留在当前页面内存中，OCR 在设备本地运行，不上传、不持久保存原图。
- 导入来源标记为 `screenshot-local-ocr`，兼容旧版 `screenshot-demo` 数据。
- 不提交账号、Cookie、密钥、签名密码或用户截图。

## 验证要求

- 为版式支持判断、连续课程块合并、相邻课程拆分和 OCR 文本字段解析编写单元测试。
- 使用用户提供的参考截图验证能检测出实际课程块并进入校对页；不要把截图加入仓库。
- 运行格式检查、TypeScript 严格检查、单元测试、生产构建和现有浏览器回归。
- 确认生产构建包含本地 OCR worker、WASM 核心装载脚本和中文语言文件。
- 构建正式签名 APK，校验签名、ZIP 对齐和 SHA-256；不能把模拟器验证描述成真机验证。

## 发布要求

- 应用与 Android 版本升级到 `1.0.1`，Android `versionCode` 递增。
- 编写 `v1.0.1` 实验版 Release Notes，明确支持范围、隐私、已知限制与人工校对要求。
- 提交并推送到 GitHub，创建 `v1.0.1` GitHub prerelease，上传正式签名 APK。
- 保留现有 `v1.0.0` 正式版，不覆盖其标签或附件。
